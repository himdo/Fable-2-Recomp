# Hot-function overrides (strong-symbol copies of recompiled guest code)

## Mechanism

Recompiled guest functions (`generated/default/fable_2_recomp.*.cpp`) are emitted
as **weak `extern "C"` aliases** of `__imp__<name>` (the always-original entry
point), and `generated/default/fable_2_register.cpp` registers the **alias** in
the indirect-dispatch table (`registrar->SetFunction(0xADDR, <name>)`).

Defining a **strong** `extern "C"` symbol with the same name in the `fable_2`
target therefore intercepts *both* direct `bl` calls and `bctrl` dispatch for
that guest function. `__imp__<name>` remains the original if you want to fall
back or forward.

```cpp
// src/core/hotfunc/<category>/<name>.cpp
#include "fable_2_pch.h"
extern "C" void __imp__sub_XXXX(PPCContext& ctx, uint8_t* base); // original
extern "C" void sub_XXXX(PPCContext& __restrict ctx, uint8_t* base) {
  // optimized copy, or: __imp__sub_XXXX(ctx, base);
}
```

(See `src/diagnostics/fps_probe.h` for the wrapper-style variant.)

Transforms:
- **nv** — non-volatile `GV*/SV*` guest-RAM access (rules below).
- **mfmsr** — `mfmsr` reads `ppc_global_lock_count_()` (std::atomic) directly
  instead of fence + `REX_CHECK_GLOBAL_LOCK()` (mutex acquire/release).
- **glock** — caches `rex::thread::global_critical_region::mutex()` in a
  per-thread reference so the inlined `REX_ENTER/LEAVE_GLOBAL_LOCK` skip the
  per-use DLL call; same mutex, same lock/unlock order.
- **gt** — inlines `GetTimebase_8221EB58` with the exact codegen expressions
  (sub_82276C30 only; 7 sites).
- **batched yield** — `YieldAndCheckThreshold_82CBD098`: the work-loop
  `NtYieldExecution` (SDK `MaybeYield()` = `SwitchToThread()` +
  `MemoryBarrier()`) was the single biggest cost in the 475 chain (~13.7%
  of total CPU; the loop calls it every iteration and each real
  SwitchToThread rotates the CPU to the next ready guest thread). The
  override replaces it with `fable2::hotfunc::BatchedYield()`
  (`src/core/hotfunc/hotfunc_yield.h`): every Nth call does the real
  SwitchToThread, the others take a full memory fence; guest-visible
  result unchanged (r3 = X_STATUS_SUCCESS, then the constant threshold
  math). N is runtime-tunable: `[perf] hotfunc_yield_every` in
  fable2_config.toml (default 8; 1 = original; 0 = never yield).
- **hoist** (sub_82276C30 only, OFF by default, `HOTFUNC_HOIST=1` to
  re-test) — per-iteration hoist of the time-constant doubles; see the
  hoisting rule below for why it is off. (The older
  `tools/make_hotfunc_copy.py` was superseded by this tool.)

## Hand-tuned overrides

Some functions are rewritten as readable C++ rather than kept as literal
copies of the recompiler output (named locals, `gload8/32/64` / `gstore8/32/64`
helpers, a `vcall()` thiscall helper, per-line disassembly references, and a
decompiled guest-logic sketch in the header). Currently:

- `frame/ProcessGameFrame_82276C30.cpp`
- `player/CallActivePlayerMethod_821A11E8.cpp`
- `refcount/ConstructRefCounted_8222CF18.cpp`
- `frame/DispatchFrameCallback_821A6010.cpp`
- `os_notifications/DispatchOsNotifications_82185080.cpp`
- `entity/InitializeGameEntity_8233CAC8.cpp`
- `subsystems/LazyInitSubsystemA_8217FD08.cpp`
- `subsystems/LazyInitSubsystemB_822C6C60.cpp`
- `os_notifications/PollAndProcessOsNotifications_8229A9D8.cpp`
- `refcount/ProcessGrowBitArray_821EC668.cpp`
- `player/QueryActivePlayerMethod_821EC8A0.cpp`
- `frame/RegisterFrameCallback_821DCF10.cpp`
- `entity/ProcessGameStateUpdate_821C9008.cpp`
- `refcount/Release_RefCounted_821C67D8.cpp`

**Mechanism (survives regeneration):**
- The first line of the file is `// Hand-tuned override ...`. The generator's
  `emit()` refuses to overwrite any file whose first line starts with that
  marker (`HAND_TUNED_MARKER`), and its `FUNCTIONS` entry is
  `dict(hand_tuned=True)` so a full run skips it.
- The `FUNCTIONS` entry in `tools/make_hotfunc_overrides.py` therefore carries
  no transform list for these (the transforms they started from are noted in
  the file header for reference).
- Re-run `python tools/make_hotfunc_overrides.py` any time; hand-tuned files
  are left byte-for-byte untouched.

**Fidelity rules (must stay behavior-identical to the generated copy):**
- Same guest RAM reads/writes (addresses + order), same dispatch targets and
  guest return addresses, same `r3`/`r1`/`lr`/`r30`/`r31`/`r12`/`ctr`/CR side
  effects at every call site and on return, same trap calls.
- Only *volatile non-argument* GPRs (r7-r11, etc.) may end up holding
  different values than the generated copy - the PPC32 ABI makes them
  caller-saved, so well-formed guest code writes them before use. Never
  deviate on r2, r13-r30, r1, or the argument registers. Document any such
  deviation in the file header.

**Optimizations allowed in a hand-tuned rewrite** (document each in the
header with the reason it is unobservable):
- Drop the `mfmsr`/`mtmsrd`/`mtmsrd` MSR interrupt-lock sequence and its
  `std::memory_order_seq_cst` fences. `ctx.msr` is **write-only** across the
  whole recompiled binary: every `mtmsr` uses the self-preserving
  `(REG & 0x8020) | (ctx.msr & ~0x8020)` pattern, `mfmsr` reads the global
  lock count (not `ctx.msr`), and the 0x8020 bits are masked away by every
  later `mtmsr`. The global critical-region mutex already supplies the
  ordering the fences provided. (Used in `ConstructRefCounted`.)
- Reduce a `lwarx`/`stwcx.` retry loop to a plain read-modify-write inside
  the global critical region, when every writer of that word takes the same
  global lock (so the CAS can never fail). (Used in
  `ConstructRefCounted`'s global live-object counter @ `0x83496EB8`.)

## Rules for new copies

- Copy the recompiled body **verbatim first**, verify identical behavior, then
  optimize incrementally (a ~900-line function is hard to bisect otherwise).
- Keep all register/CR/XER/FPSCR/MSR side effects the original emits (callers
  and the post-call dispatch depend on `ctx` being exactly as the guest code
  left it — including dead-looking registers). Hand-tuned rewrites may drop
  writes to *volatile non-argument* registers (r0-r12 except arguments) since
  the PPC32 ABI makes them unobservable to callers - never r2/r13-r30;
  document any such deviation in the file header.
- Non-volatile access is safe per-function: each recompiled function is
  compiled independently, calls are opaque, so CSE only happens inside basic
  blocks. Verify the function touches **no MMIO** (no `REX_MM_*`) first.
- Hoisting globals: a whole-tree scan for literal `REX_STORE_*` writers is
  **necessary but not sufficient** — pointer-based stores and cross-thread
  writers are invisible to it. If the function's loop calls
  `YieldAndCheckThreshold_82CBD098` (or anything that yields the host thread,
  e.g. via `NtYieldExecution`), other guest threads run MID-iteration, so any
  global they touch may change between a hoisted load and its uses. The
  time-constant hoist for `0x82276C30` failed exactly this way (game hung on
  the loading screen); it is disabled by default. Verify candidate hoists
  with a runtime logger (log the value per call / every N iterations and
  confirm it never changes within an iteration) before shipping them.
- Adding inlined callees: copy the callee's codegen expressions **exactly**
  (including quirks, e.g. `GetTimebase`'s zero-extend `rotlwi r10,r11,0`).
- `tools/apply_recomp_patches.py` patches the generated code, not your copy:
  if a patch ever targets an overridden function, re-apply it to the copy.
- Regenerate all copies with: `python tools/make_hotfunc_overrides.py`
  (or pass function names to generate a subset).
